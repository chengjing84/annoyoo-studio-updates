# AI 姿势与服装参考库 · 中文版

> 288 组姿势 / 1,439 张多角度参考图，加上 1,407 套服装 / 8 个分类，整合为同一个本地项目。

顶部使用 **ANNO_Yoo杏野** 艺术签名，提供作者 B站、抖音主页链接，并保留姿势、服装两个原项目入口。创作台先显示人物参考，再显示姿势与服装；桌面布局按窗口高度适配参考图和结果预览，默认在首屏展示至生成按钮。长姿势说明、生成设置与 LoRA 按需展开。

图库筛选栏右侧的 **姿势 / 服装** 页签用于切换两套图库。服装拥有完整的分类搜索、详细 / 简洁卡片、大图前后浏览、原图下载与复制功能；两边的筛选状态独立保留。生图区的“选服装”会定位到服装图库，点击卡片的“选用这套服装”或大图中的“用此服装生成”即可带回生图区。

浏览图库和生成图片统一双击 **`启动创作台.cmd`**（优先本机端口 8765，被占用时自动选择空闲端口）。统一版首次启动选择 **外接生图 API / 内置 WebUI / 接入已有 ComfyUI**，再显示对应配置；完整操作见 [统一版使用说明](docs/统一版使用说明.md)。

当前采用 **完整整合包（不含模型）＋ GitHub 小型更新** 的发布方式。完整包附带 Node.js、完整图库、Python、PyTorch 与 ComfyUI，放到夸克供首次下载；GitHub 仅提供项目介绍和程序更新。模型继续独立下载，手动放入 `models/` 后点击检测即可。修改 `config/distribution.json` 的版本后，使用 `python -B scripts/build-integrated-release.py` 生成两个未压缩的发布目录。更新保留 `runtime/`、`models/`、`output/` 和 `.local/`。安装方式记在 `.local/studio-settings.json`；源码通过 `config/edition.json` 选择统一启动入口。

## 这是什么

这是一套面向 AI 绘画 / 3D / 摄影参考的本地图库，整合原作者的姿势库与服装库。姿势库原有内容如下，服装数据和维护工具也已并入当前目录：

1. **全量镜像** —— 1439 条记录对应的 1439 张缩略图（JPG 300×400）与 1439 张原图（PNG 900×1200）全部落地，共 2878 个文件 / 659.5 MB。
2. **完整汉化** —— 日文字段逐条译为中文，覆盖 4 个体系、26 个分类、288 个姿势名、5 个视角，零遗漏。
3. **可用的前端** —— 零依赖响应式画廊，完整实现原站的分类筛选、多角度切换、分组浏览、灯箱导航与原图下载，并针对手机重新设计布局。

## 页面功能

- 筛选栏右侧切换姿势 / 服装，无需启动另一个项目
- 服装 8 类、1,407 套，支持中文多词、英文、颜色材质和 ID 搜索
- 服装支持详细 / 简洁卡片、真实 PNG 尺寸、大图上下套导航、原图下载和复制描述
- 4 个体系页签，显示各体系的图片数与姿势组数
- 姿势名、编号、ID、分类关键词搜索，支持 `/` 快速聚焦
- 动作分类、5 种视角组合筛选，可一键重置
- **按姿势分组 / 逐张浏览**双模式，分组卡片带多角度缩略图
- 悬停或点击缩略图切换主图角度，点击卡片打开灯箱
- 灯箱先显示缩略图、再加载 900×1200 原图，支持直接下载 PNG、复制 ID、新窗口打开
- `← / →` 切换角度，`↑ / ↓` 切换姿势，`Esc` 关闭；手机支持左右滑动
- PC 多列网格、手机双列网格，移动端筛选面板可展开/收起
- 使用指南与注意事项弹窗，页脚标注图片来源与维护者链接

## 逐图片姿势词条

每张原图按自己的 ID 关联一份词条，同组的正面、侧面、俯视和仰视分别分析。打开大图即可查看动作描述、视角、检索关键词及遮挡不确定项；切换角度时词条同步切换。支持复制描述，并可直接搜索“单手支撑”“双腿前伸”等动作细节。点击“用此姿势生成”后，生图区显示当前角度的词条，本地服务自动将动作描述合入实际提交给 Qwen-Image 2.1 的提示词，无需复制。勾选“使用姿势图的拍摄视角”时也会加入视角描述；关闭时机位按用户画面要求设置。动作词条不覆盖用户输入的人物、服装、场景或画风，切换姿势后也不会叠加旧词条。

`data/pose-descriptions.json` 的 `items` 以图片 ID 为键，每条包含：

- `动作描述`：可见的躯干、头部、手臂、腿脚、支撑和接触关系。
- `视角描述`、`关键词`、`不确定`：机位标签、动作细节与不能从当前图确定的部位。
- `原图SHA256`、`模型`、`标注方式`、`审核状态`：用于追溯词条与实际图片的对应关系。二次视觉核对由 Codex 完成，属于 AI 看图核对，不表示人工逐条审核。

初稿使用本机 Ollama 中的标准 `qwen3.5:9b` 对每张原图独立分析，结合原有角度和动作短名交叉校验；复杂机位、手势和双人重叠条目另经二次视觉核对，以可见图像为准修正。词条可辅助检索和提示词编写，不包含三维骨架或精确关节角度。

如需再次生成或断点续跑，先启动已安装 `qwen3.5:9b` 的本机 Ollama，再在项目根目录运行：

```powershell
python scripts/caption-poses.py --root . --base http://127.0.0.1:11434 --workers 1
```

脚本会保留 `.local/pose-descriptions.raw.jsonl` 中的原始响应和原图指纹，已有词条自动跳过；`data/pose-description-reviews.json` 中的复核版本优先保留。查看和复制已生成词条无需运行 Ollama。

## 本地预览

### 使用 Qwen-Image 2.1 生成图片

1. 双击项目根目录的 `启动创作台.cmd`，启动本地服务并打开创作台（优先使用 `http://127.0.0.1:8765`）。
2. 首次选择内置 WebUI 并准备环境与模型，或接入已有 ComfyUI（默认地址 `http://127.0.0.1:8188`）。已有环境可连接已运行的服务，也可指定安装目录和 Python 启动。
3. 选择姿势、服装或同时选择两者。姿势在下方图库直接点击卡片底部的 **选用此姿势**，采用卡片当前显示的视角；也可打开大图后点击靠前的 **用此姿势生成**。分组和逐张浏览均支持快捷选用，已选姿势会高亮，选用后返回创作台并显示参考图。服装在筛选栏右侧切换到 **服装**，或在生图区点击 **选服装**，进入 1,407 套服装的完整图库。点击 **选用这套服装** 或打开大图后点击 **用此服装生成**。两种参考均可单独移除。
4. 最多上传两张参考图。人物参考1提供主角色身份；第二张用途默认是 **第二位人物**，也可选择 **环境场景**，需要时手动选择 **同一人物补充**。用途在上传前即可选择，不因增减图片自动重置。有人物参考1时文字可留空；只有环境图时仍需填写人物描述。
5. 点击生成后可查看排队状态、采样进度和结果，支持下载或将结果用作下一次的参考图。生成图自动保存到项目根目录 **`output/`**，页面会显示保存的文件名。

需要 Node.js 22 或更新版本，不需要安装 npm 依赖。启动脚本沿用已经运行的 ComfyUI，不会停止其现有任务。本地服务仅监听 `127.0.0.1`。ComfyUI 先将生成图写入其 `output/pose_gallery/`，画廊服务随后自动保存到本项目的 `output/`；关闭网页后仍会完成保存，只需保持画廊服务和 ComfyUI 运行。保存完成后，结果预览和下载直接读取项目文件，ComfyUI 关闭后仍可访问。上传图片保存在 ComfyUI 的 `input/pose_gallery/`。本项目 `.local/` 仅记录任务、参考图标识和服务日志，`output/` 已加入版本管理和静态发布忽略规则。

**固定标准版：** 自动选择 `qwen_image_2.1_int8_convrot.safetensors` 或 `qwen_image_2.1_bf16.safetensors`，配套 Qwen3-VL 8B 编码器与 `qwen_image_2.1_vae_bf16.safetensors`。不会自动选用 Turbo、Lightning 或其他合并模型，默认不加载任何 LoRA。默认 30 步、CFG 1、Euler / Simple；高级设置支持 20–50 步、图片尺寸与种子。

**可选 LoRA：** 在 **生成设置 → LoRA** 中展开设置，接入数量可选 **0–8 个**，初始为 **0 · 不使用**，刷新页面也恢复为 0。每个条目独立选择模型和权重，初始权重为 1，支持 -100 至 100，权重 0 的条目跳过加载。列表直接读取本机 ComfyUI 的 LoRA 文件，可点击刷新；新文件放到 ComfyUI 的 `models/loras/` 或其已配置的 LoRA 目录。请自行选择与 Qwen-Image 2.1 兼容的文件，触发词写在画面描述中。

LoRA 按列表顺序通过 `LoraLoaderModelOnly` 串接在基础模型与 Qwen 缓存节点之间，只修改扩散模型，不修改文本编码器。数量为 0 时不生成任何 LoRA 节点，沿用原有工作流；缺少 LoRA 加载节点不影响默认生成。服务端验证数量、重复项、权重范围以及所选文件是否存在。每次生成的模型文件名和权重会记录到任务与 PNG 工作流元数据中。

参考图统一按“人物身份参考 → 姿势 → 服装 → 环境场景”排序，未选择的项目跳过，保证有人物时先提供角色身份。人物身份参考可包含人物A、人物B，或A的补充视角；环境图只在选为场景用途时进入环境位置。没有人物图时，姿势或服装图仍可结合文字生成新角色。第一张图等比缩放并补白到目标尺寸，其余等比缩放到最长边 1024 像素。最多四张图直接进入 Qwen-Image 2.1 的原生多图编辑编码节点，图像与提示词使用同一份参考顺序，保持编号一致。

**PE 格式适配：** 当前生成始终包含姿势、服装或人物等参考图，采用官方 [PE-I2I 系统提示词](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-I2I/blob/main/system_prompt.txt) 的编辑指令格式。正文以操作开头，说明逐图分工、变化与保留要求，输出为一个连续段落；只有一张输入图时称“图像”，两张及以上使用与实际输入顺序一致的 `<image1>`、`<image2>` 等标签。保留角色身份、双人 A/B 分工及上半身取景约束。

在生图区展开 **查看最终提示词**，点击 **预览当前设置**，可查看或复制正文和 `rewritten_prompt` / `wh_ratio` / `ratio_follow` JSON。预览只运行本地模板，无需上传参考图或连接 ComfyUI，也不会提交生图任务；仍需启动画廊服务。调整参考、描述、机位、背景或画面尺寸后，旧预览会失效。生成成功提交后，面板更新为实际提交的提示词，记录同时保存到任务与 PNG 工作流元数据。

画面尺寸由页面设置明确指定，`wh_ratio` 为该尺寸约分后的宽高比，`ratio_follow` 为空；编码节点仅接收 `rewritten_prompt` 正文，尺寸由图像节点传递，负面提示词为空。这是现有本地模板对官方 PE 格式的适配，未下载或调用独立的 PE-I2I 增强模型，也不将纯文生图的英文长描述规则套用到有参考图的编辑任务。

**第二张参考图的用途：** 默认双人物模式将人物1绑定动作描述中的A、人物2绑定B，分别保留身份、发型、体型；未选服装时各自保留原穿搭，不将一人的脸和服装覆盖到另一人。A/B的前后、承托与接触关系采用姿势词条；未标注A/B时，默认较前或左侧为A、较后或右侧为B。场景模式只提取空间布局、建筑、地面、家具、透视与光照，图中的人不作为角色或增加人数；该模式优先采用场景图环境，隐藏“保留人物图背景”选项。同人补充仅作为显式选项，不再默认合并身份。

人物参考1配合第二张环境图时，也可不选姿势与服装，直接将人物融入场景；默认保留人物身份、原穿搭和整体动作，用环境图决定空间、透视、光照与承托关系。

请求会同时携带 `referenceIds` 和逐图对应的 `referenceRoles`（`person1`、`person2`、`scene`、`supplement`），避免只有第二张场景图时被错误地当成主角。单人物模式为 `single-character`；旧请求未提供模式时，一张图按单人物、两张图按双人物处理。场景图单独上传需要文字描述角色。双人姿势只有人物A加场景时，B由用户描述或不同外观的配角补足，场景图不参与B的身份。

**角色动作规则：** 选了人物和姿势时，优先从人物图保留面部身份、发型、头颈及画风，身体主动改为姿势参考中的动作；同时选服装时，服装只提供穿搭，不能提供身体或头部结构。多视图角色设定表的正面、侧面、背面和面部特写作为同一身份的参考，不复制成并排立绘或额外人物。指令明确排除服装展示中的无头、空领口和隐形人体结构。两位人物模式分别绑定两张人物图，并与双人姿势位置对应。

**上半身取景限制：** “上半身单人”体系及对应 `upper80v2_` 姿势使用独立的半身指令，画面限定为完整头顶至腰线附近，保留脸、发型、手势及必要前臂，不补出大腿、膝盖、脚或鞋。服装只参考上身可见的衣领、上衣、外套、袖口和配饰，自动服装文字不再加入鞋袜、半身裙等画外单品，不为展示全套衣服拉远镜头。关闭“使用姿势图的拍摄视角”只改变机位，不解除半身限制；需要全身时请改选全身姿势。

**人物换装规则：** 未选姿势时，以首张人物图作为换装底图，保留身份、头颈、发型、身体比例和可见肢体；没有明确的动作、机位要求时，也保留人物原有姿态和取景。服装图只提供服装、鞋和配饰的款式与质感，不带入无头展示结构、站姿和陈列背景。服装中文描述作为辅助，重叠标签不拆成多件衣物，细节以服装图为准。两张同人物参考用于补充外貌，两位人物模式则分别保持身份并构成同一场景。用户明确指定的动作、构图、场景和画风仍带入最终指令。

可以选择是否沿用姿势图的机位、是否保留首张已上传人物图的背景；单人姿势搭配两位人物时，动作应用于第一位，第二位自然站在旁边，可用文字调整。生成模型对身份、动作和场景的遵循程度仍会受参考图及提示词影响。

服装素材从本机 `F:\ai-costume-gallery-zh-main` 整合到 `costume/{thumbs,img,png}/`，不依赖原项目启动。中文元数据位于 `data/costume-zh.json`，离线读取副本为 `data/costume-zh.js`。原作者、素材使用说明及来源保留在 `costume/SOURCE.md` 与 `costume/LICENSE`；图片遵循原站条款，项目源码许可不改变素材权利。

服装维护工具也已合并，不会覆盖姿势库的同名数据与脚本。在当前项目根目录运行：


### 整合包目录准备

本地版已支持 **内置 ComfyUI / 连接已有 ComfyUI**。点击创作台右上方 **本地引擎与模型**，填写连接地址或保存内置模式；已有环境可用本机或局域网 HTTP / HTTPS 地址。内置模式支持额外模型根目录，按原有 `diffusion_models/`、`text_encoders/`、`vae/`、`loras/` 结构识别，不会搬移原目录。

**模型独立管理：** `config/model-catalog.json` 固定了官方 Qwen-Image 2.1 标准版 INT8 主模型、INT8 文本编码器和 BF16 VAE 的版本、直链、字节数和 SHA-256。模型管理可逐个或顺序下载三件套，断点文件保存在模型目录，完成后校验再启用；也可从绝对路径或浏览器文件选择导入，原文件保留。导入需选择与清单对应的文件。外部 ComfyUI 的兼容 BF16/FP8 模型仍由原工作流自动识别。夸克入口目前留空，之后填写清单中的 `quarkUrl`、`quarkCode` 即可显示。

**独立运行环境：** 本地版优先使用 `runtime/node/node.exe` 和 `runtime/comfyui/python/python.exe`，不要求用户另装 Node/Python。内置 ComfyUI 不加载原环境的第三方节点或个人配置；它自己的日志、用户配置和中间输出放在 `.local/`。通过页面停止内置引擎只结束本程序启动的进程；**停止创作台.cmd** 会核对服务身份后关闭本包服务，已有 ComfyUI 不受影响。存在未完成生图任务时禁止切换连接或停止服务。

打包工具 `scripts/build-local-package.py` 从已验证的 ComfyUI/Python 提取核心和必要依赖，创建隔离运行环境，再按白名单复制页面、图库、代码和运行环境，排除模型与用户数据。源环境的安装清单和实际导入版本可能不一致，因此发布前还需通过独立启动和真实工作流验证。使用源 ComfyUI 的 Python 执行：

```powershell
F:\ComfyUI\python\python.exe -I -B scripts/build-local-package.py --comfy-root F:\ComfyUI\ComfyUI --python-root F:\ComfyUI\python --node "C:\Program Files\nodejs\node.exe" --archive
```

若 `runtime/` 已准备好，追加 `--reuse-runtime`；目录已存在时打包工具不会覆盖，请用 `--name` 指定新版本目录。输出位于 `release/`，ZIP 支持 ZIP64，并附 SHA-256。首个内置环境面向 Windows x64 / NVIDIA / CUDA 13.0；显卡驱动由系统提供，外接模式使用原 ComfyUI 的环境。

**外接生图 API 版：** 保留人物、姿势、服装和场景参考，支持自定义接口地址、API Key、模型名称，以及 Images multipart / Qwen JSON 两种协议。只附带 Node.js 与完整图库，不包含 ComfyUI、Python 或模型。使用 `python scripts/build-api-package.py --archive` 制作独立整合包；同样可通过 `--name` 指定新版本名称。设置与任务分别保存在 `.local/api-settings.json`、`.local/api-generation-state.json`，打包脚本不会复制个人配置和生成结果。操作方法见 [API 版使用说明](docs/API版使用说明.md)。

项目运行文件与素材保留在原路径：`index.html`、`assets/`、`data/`、`thumbs/`、`img/`、`costume/`，以及启动入口和 `scripts/` 下的服务与工作流。源码模式可继续使用系统 Node.js 22 或更新版本；本地整合包则附独立环境，模型另行准备。

制作干净的整合包时排除 `.local/`、`output/`、`__pycache__/`、`*.pyc`、`*.part`、`dist/` 和开发测试文件 `*.test.mjs`。现有 `output/` 生成图和 `.local/generation-state.json` 任务记录属于本机用户数据，清理开发产物时保留；新环境会在启动后自行建立运行目录。`.local/pose-descriptions.raw.jsonl` 是姿势标注的断点记录，不参与图库运行，但可用于继续维护词条。

下载与校验工具现在将报告统一写入 `.local/reports/`，正式 `data/` 只保留素材数据、离线副本、译文与来源记录。服装的缩略图、WebP 预览和 PNG 原图分别用于卡片、创作台预览和编辑/下载；中文 JSON 与 JS 副本分别服务 HTTP 和直接打开网页的离线模式，均需保留。两个项目的许可与 `costume/SOURCE.md` 来源说明一并保留。

若 ComfyUI 使用不同端口，在创作台的 **安装与模式 → 接入已有 ComfyUI → 连接服务地址** 中填写实际地址，例如 `http://127.0.0.1:8189`。

页面与本地服务需要位于同一台电脑。统一入口由 `scripts/studio-server.mjs` 启动，并按所选方式接入对应生图服务。静态托管或直接打开 `index.html` 仍可浏览图库；日常使用和生图统一运行 `启动创作台.cmd`。

## 部署到 Cloudflare Pages

仓库为纯静态站点，无框架、无依赖。

**方式一：GitHub 自动部署（推荐）**

1. 登录 Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. 选择本仓库 → 生产分支 `main`
3. 构建设置照抄：

   | 字段 | 值 |
   | --- | --- |
   | Framework preset | `None` |
   | Build command | `bash scripts/build.sh` |
   | Build output directory | `dist` |

4. **Save and Deploy**，约 2–5 分钟得到 `https://<project>.pages.dev`
5. 之后每次 `git push` 自动重新发布

> ⚠️ **不要**把 Build output directory 直接填 `/`。仓库根目录含 `.git`（数百 MB），
> Cloudflare 会把它当静态资源扫描，pack 文件超过 25 MiB 单文件限制会导致构建失败。
> `scripts/build.sh` 将页面、分享配置、`assets/`、`data/`、`thumbs/`、`img/`、`costume/` 拷贝到 `dist/`。
> 若确实想用根目录，仓库已附 `.assetsignore` 兜底排除非站点文件。

> 当前素材共 7,099 个文件：姿势 2,878 个，服装 4,221 个。运行状态、用户生成图和工具报告不属于静态发布内容。

**方式二：命令行直传**

```bash
bash scripts/build.sh
npx wrangler pages deploy dist --project-name ai-pose-gallery-zh
```

`_headers` 已为 `img/`、`thumbs/` 配置一年期强缓存，图片不会重复回源。
